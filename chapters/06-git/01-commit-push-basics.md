# Git Basics — commit, push и базовый цикл изменений

## Главная схема

```text
Working Directory (рабочая директория)
↓
git add
↓
Staging Area (область подготовленных изменений)
↓
git commit
↓
Local Repository (локальный репозиторий)
↓
git push
↓
GitHub / Remote Repository (удалённый репозиторий)
```

## Commit (коммит)

**Commit (коммит)** — зафиксированный снимок изменений в истории Git.

Он сохраняет:

- какие файлы изменились;
- что именно изменилось;
- автора;
- время;
- сообщение commit (коммита);
- уникальный идентификатор.

Пример:

```bash
git commit -m "Fix CTR calculation"
```

Commit (коммит) создаётся локально и сам по себе ничего не отправляет на GitHub.

## Push (пуш)

**Push (пуш)** — отправка локальных commit (коммитов) в remote repository (удалённый репозиторий), например GitHub.

```bash
git push
```

Или явно:

```bash
git push origin main
```

Где:

- `origin` — имя remote repository (удалённого репозитория);
- `main` — branch (ветка).

## Git add

`git add` помещает выбранные изменения в **Staging Area (область подготовленных изменений)**.

Например:

```bash
git add analytics.py
```

или все текущие изменения:

```bash
git add .
```

Staging Area (область подготовленных изменений) позволяет выбрать, какие изменения попадут в следующий commit (коммит).

## Git status

```bash
git status
```

показывает текущее состояние файлов:

- modified (изменённые);
- staged (подготовленные);
- untracked (неотслеживаемые).

## Repository (репозиторий)

**Git Repository (Git-репозиторий)** — проект, историю которого отслеживает Git.

Внутри локального проекта Git хранит служебные данные в директории:

```text
.git/
```

## Branch (ветка)

**Branch (ветка)** — отдельная линия разработки.

Пример:

```text
main
A──B──C
       \
        D──E
        feature/new-report
```

Изменения можно делать отдельно от основной ветки, а затем объединить.

## Базовый рабочий цикл

```bash
git status
git add .
git commit -m "Add SEO report filters"
git push
```

По смыслу:

```text
изменить файлы
↓
выбрать изменения
↓
зафиксировать версию
↓
отправить её на GitHub
```

> [!IMPORTANT]
> ## Ключевые идеи — обязательно запомнить
>
> - **Commit (коммит)** — сохраняет точку истории Git локально.
> - **Push (пуш)** — отправляет commit (коммиты) в remote repository (удалённый репозиторий).
> - **git add** — выбирает изменения для следующего commit (коммита).
> - **Staging Area (область подготовленных изменений)** находится между рабочими файлами и commit (коммитом).
> - Типичный цикл: `change → add → commit → push` — `изменить → подготовить → зафиксировать → отправить`.
