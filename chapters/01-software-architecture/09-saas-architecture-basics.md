# SaaS Architecture Basics — базовые понятия SaaS

## Что такое SaaS

**SaaS — Software as a Service (программное обеспечение как услуга)** — модель, при которой программа предоставляется пользователю как постоянно работающий онлайн-сервис.

Обычно пользователь:

- регистрируется;
- работает через браузер;
- не разворачивает серверную часть у себя;
- получает обновления автоматически;
- платит по подписке или за использование.

Схема:

```text
User (пользователь)
↓
Browser (браузер)
↓
SaaS Application (SaaS-приложение)
↓
Backend / Database / APIs
(бэкенд / база данных / API)
```

## B2B и SaaS — разные понятия

**B2B — Business-to-Business (бизнес для бизнеса)** отвечает на вопрос:

> Кому продаём?

**SaaS — Software as a Service (программное обеспечение как услуга)** отвечает на вопрос:

> Как предоставляем программный продукт?

Поэтому **B2B SaaS** — это SaaS-продукт для компаний.

## Multi-tenancy (мультитенантность)

**Tenant (тенант)** — отдельный клиент или организация внутри SaaS.

Одна SaaS-платформа может обслуживать множество независимых клиентов:

```text
              SaaS Platform (SaaS-платформа)
                       │
          ┌────────────┼────────────┐
          │            │            │
      Tenant A      Tenant B      Tenant C
      Клиент A      Клиент B      Клиент C
```

Данные разных tenants (тенантов) должны быть изолированы.

Например:

```text
sites
├── id
├── tenant_id
└── domain
```

`tenant_id` помогает определить владельца данных.

## Organization, User и Role

В B2B SaaS часто используется модель:

```text
Organization (организация)
├── User (пользователь) — Owner (владелец)
├── User (пользователь) — Admin (администратор)
├── User (пользователь) — Editor (редактор)
└── User (пользователь) — Viewer (наблюдатель)
```

Отсюда появляются:

- Authentication (аутентификация) — кто пользователь;
- Authorization (авторизация) — что ему разрешено;
- Tenant Isolation (изоляция клиентов) — какие данные он может видеть.

## Plans, Subscriptions и Limits

Для SaaS характерны:

```text
Plan (тариф)
Subscription (подписка)
Feature (функция)
Limit (лимит)
```

Например:

```text
Business Plan (бизнес-тариф)
├── max_sites = 30
├── max_users = 10
├── ai_analysis = true
└── update_frequency = daily
```

## Основные модели оплаты

### Subscription (подписка)

Фиксированная оплата в месяц или год.

### Per-seat pricing (оплата за пользователя)

Например:

```text
20 EUR / user / month
```

### Usage-based pricing (оплата по использованию)

Оплата за фактическое потребление:

```text
API requests (API-запросы)
Storage (хранилище)
AI calls (AI-вызовы)
```

### Freemium (бесплатный базовый тариф)

Бесплатная версия с ограничениями и платные расширенные тарифы.

## Метрики SaaS

Полезные бизнес-метрики:

- **MRR — Monthly Recurring Revenue (ежемесячная регулярная выручка)**;
- **ARR — Annual Recurring Revenue (годовая регулярная выручка)**;
- **Churn (отток)** — доля ушедших клиентов;
- **CAC — Customer Acquisition Cost (стоимость привлечения клиента)**;
- **LTV — Lifetime Value (ценность клиента за всё время)**;
- **Retention (удержание)** — доля клиентов, которые продолжают пользоваться сервисом.

## SaaS с точки зрения архитектуры

Для MVP (минимально жизнеспособного продукта) вполне подходит Modular Monolith (модульный монолит):

```text
SaaS Backend (SaaS-бэкенд)
├── auth/             (аутентификация)
├── organizations/    (организации)
├── collectors/       (сборщики данных)
├── analytics/        (аналитика)
├── rules/            (правила)
├── reports/          (отчёты)
├── notifications/    (уведомления)
└── billing/          (биллинг)
```

Микросервисы не являются обязательным условием SaaS.

## Background Jobs (фоновые задачи)

Долгие операции лучше выполнять вне обычного HTTP request (HTTP-запроса).

Например:

```text
User (пользователь)
↓
POST /analysis
↓
Job (задача)
↓
Worker (фоновый исполнитель)
↓
Analytics (аналитика)
↓
Result (результат)
```

UI (интерфейс) в это время может показывать статус выполнения.

## AI SaaS

Плохой AI-продукт легко сводится к:

```text
UI (интерфейс)
↓
LLM API
```

Более устойчивый продукт создаёт ценность вокруг модели:

```text
Data (данные)
↓
Domain Logic (доменная логика)
↓
Rules (правила)
↓
Prioritization (приоритизация)
↓
AI
↓
Recommendation (рекомендация)
```

> [!IMPORTANT]
> ## Ключевые идеи — обязательно запомнить
>
> - **SaaS** — программный продукт, предоставляемый как постоянно работающий сервис.
> - **B2B** определяет тип клиента, а **SaaS** — модель предоставления программы.
> - **Multi-tenancy (мультитенантность)** позволяет одной платформе обслуживать несколько независимых клиентов.
> - Данные tenants (тенантов) должны быть изолированы.
> - Для B2B SaaS типичны Organizations, Users, Roles, Plans, Subscriptions, Billing и Limits.
> - SaaS MVP можно начинать с Modular Monolith (модульного монолита).
> - Главная ценность AI SaaS должна быть шире простого проксирования запросов в LLM API.
