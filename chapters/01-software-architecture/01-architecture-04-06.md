# 0.4 Компоненты

## Компонент

Самостоятельная часть системы с одной ответственностью.

Примеры: - Collector - Analytics - Rule Engine - Report Generator - AI
Advisor

## Принцип

Один компонент = одна причина измениться.

## Хороший компонент

-   делает одну работу;
-   имеет понятный вход;
-   имеет понятный выход.

------------------------------------------------------------------------

# 0.5 Контракты и зависимости

## Контракт

Договор между компонентами о формате взаимодействия.

Компоненты должны знать контракт, а не внутреннее устройство друг друга.

## Adapter

Внешний API ↓ Adapter ↓ Внутренний формат

Изменение внешнего API должно менять только адаптер.

## Dependency

Зависимости должны идти в одну сторону.

A → B

а не

A ↔ B

------------------------------------------------------------------------

# 0.6 Ответственность

## Ответственность

Причина существования компонента.

Папка должна отражать ответственность.

Хорошо: analytics/ notifications/ reports/

Плохо: utils/ misc/ helpers/

## Когда utils допустим

Только для универсального кода: - UUID - работа со временем - общие
математические функции - логирование

Бизнес-логика никогда не должна жить в utils.
